# Santa V11 — Round 3

Fixed Dev100, same split as rounds 1/2. Fresh portfolio: 16,437; V10 reference 16,494 (-57, 0.35%); V11 round 2 reference 16,583 (-146, 0.88%). All 100 puzzles and all seven routes were independently replayed by repo_verify.py. 50 improve, 17 tie, 33 regress vs V10. No history of solution programs is used for constructing a fresh solution. The previous scores are used only by the analysis script. No GitHub modification. Holdout and full1000 not run.

## Methods
- `bilayer.cpp`: build a bounded second virtual dictionary from active × stratified one-step probes and sampled virtual × virtual pairs; at most 240,000 distinct second-layer values. Search inverse operands for exact +,-,*,/ and allow second-layer quotients, residuals and sampled bases at the top recursion level. Reconstruct the dependency union into a DAG, prune unused nodes, schedule and replay. Generated from `order.cpp` using `make_bilayer.py`. One recipe per second-layer value and bounded sampling are heuristics, not complete bidirectional search.
- `hyperunion.cpp`: replace additive hyperedge cost with popcount of the union of dependency bitsets plus one new vertex. A single label per vertex, heuristic tie perturbations and 24 LNS iterations do not guarantee global optimum. Register recomputation still not part of graph selection.
- `run_portfolio.py`: construct all four seed DAGs fresh, then run original union, hub, and setunion hypergraph optimizations. Select the least actual instruction count among seven verified programs for each row. This is not selection from historic output files. `run3.py` was used for the earlier isolated bilayer ablation. `REPORT.json` includes per-route totals, actual fresh portfolio, independent verification, and score-only reference comparisons. The earlier score-only paired estimate (16,480) is not the new fresh portfolio.

## Reproduction
Linux Python 3.13.5, C++17, standard library only. Compile `for x in order factor wide bilayer hyper hyperunion; do g++ -O3 -std=c++17 "$x.cpp" -o "$x"; done`. Use a new DB after recompilation because exact source/binary/Python hashes are checked. `python run_portfolio.py /path/to/puzzles.csv --db new.sqlite --jobs 4 --split dev --limit 10`, repeat until complete or omit limit. Use `--split holdout` or `--split all` with separate DBs. Existing fresh.sqlite completed 100 rows; the fingerprint and replay were rechecked. One batch timed out after 16 successful commits; subsequent batches resumed and completed. The isolated bilayer DB was completed before portfolio sources were added, so its old global source fingerprint differs; no unfinished rows remain. Reproduce isolated run using a new DB (`python run3.py ... --db new_bilayer.sqlite --jobs 4`). `python analysis/report3.py /path/to/puzzles.csv analysis/round2_score_reference.csv` regenerates score comparisons and independently verifies every route, including the solo ablation. Dev submission is only 100 rows, not a Kaggle submission. No official raw puzzle data included.

## Remaining limitations
Improvement over V10 is small, and only on development set. Runtime is larger than a single constructor; no wall-clock speed claim. No claim of reaching full score 164,306 or leaderboard target 124,413. Next: reduce high-bit arithmetic cost, e.g. shared quotient/remainder construction using simultaneous Diophantine approximation and modular decompositions; consider register-aware graph scoring, and freeze before evaluating holdout. No background process.
