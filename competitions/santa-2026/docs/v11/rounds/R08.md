# Santa V11 Round 8 — register-aware scheduling and multi-output synthesis

## Frozen primary candidate

`run8.py` regenerates all eight R7 routes from raw puzzle inputs. `scheduler8.py` searches no-spill topological schedules with initial registers released after last use; it allows dead operands to be overwritten, evaluates exact simultaneous live-register pressure for a given topological order, and applies deterministic-seed simulated annealing to root permutations. It retains the existing legal program if no feasible zero-recomputation order is found. Only graphs within 12 instructions of the fresh best and with existing recomputation are reconsidered. The original eight routes were reproduced exactly on each Dev100 ID (16,256 total). New primary score 16,161; 95 fewer instructions (0.584%) than R7, 333 fewer (2.019%) than V10. 12/100 improved vs R7, 78/100 beat V10. Fixed graph node count is a lower bound for schedules of that graph, not for all possible arithmetic programs.

## Separate multi-output ablation

`variants/joint8/joint.cpp` deletes two independent roots and their jointly exclusive dependency cone, identifies a new one-op shared value via intersecting inverse-arithmetic candidates, then builds both roots in two further instructions. Up to four equal-node-count moves per case are permitted; after the joint pass, rerun single-root rewriting. This is not exhaustive multi-output synthesis; it permits equal-cost moves but not uphill node-count moves. It uses one fresh `order` constructor for a controlled, cheaper experiment; all routes get identical scheduling treatment. Results: order 17,069; single-root 16,799; joint 16,793 (17 improved, 79 tied, 4 worse against single). Joint moves 363, including 361 equal-node-count moves. Mostly structural exploration, not a standalone breakthrough. Post-hoc combination of primary and separate ablation scores 16,148; **not a fresh integrated run**, and not the primary score. No earlier solutions were inputs to either experiment.

## Holdout

After the primary candidate was frozen, the first 12 IDs of the original independent holdout split were tested without tuning: V10 2,209, freshly regenerated original eight routes 2,169, R8 2,154. This is a partial result, not a claim of generalization across all 100; 88 remain. The held-out split must not be used for hyperparameter tuning. No full1000 run or GitHub changes. Several execution timeouts recovered via SQLite per-ID commits. Independent validator checked 948 Dev main programs (including winners), 300 separate ablation programs, and 116 holdout programs (including winners); all passed. Score-only historical metadata used after solving to report comparisons, not in constructors. No raw contest datasets included.

## Reproduce / resume

Place official puzzles.csv in parent directory of this package. Linux binaries and source included. Run `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run8.py ../puzzles.csv --db round8.sqlite --jobs 4 --limit 12` to replay the completed checkpoint (use a new DB name for fresh independent experiment). Resume frozen holdout with `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run8.py ../puzzles.csv --db holdout8.sqlite --split holdout --jobs 4 --limit 12` repeatedly. Fingerprint validation may require same Python/binaries; use new DB if changed. Separate ablation: `OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python variants/joint8/run_joint.py --limit 12`; fresh reproduction requires a fresh checkpoint directory or moving the old DB. Rebuild joint: `g++ -O3 -std=c++17 variants/joint8/joint.cpp -o variants/joint8/joint` (new DB required). `python reports/report8.py` independently verifies current checkpoints and emits comparison CSVs. Baseline scores only in baseline_scores.csv. Do not use checkpoint programs to seed new independent research.
