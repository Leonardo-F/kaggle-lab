# Santa V10 合入任务偏离记录

本文件记录 2026-11-27 将 V10 Full 合入 `competitions/santa-2026/` 时，与原任务书不完全一致或需要明确解释的地方。它不改变 V10 的算法实现，也不把未执行的验证描述为已完成。

## 1. 未在本次合入中完整重跑 1,000 题

**原任务：** P6 第三层"如果计算资源允许，进一步进行千题全量独立复现"；并明确"不强制本次工程合入任务再次完成数小时的千题重新求解"。

**实际：**

- 对用户交付的 `santa_v10_submission.csv` 做了官方 1,000 题全量回放：1,000/1,000 合法、164,306 步、最长 349。
- 在本机以全新 SQLite 检查点独立重解了 10 道代表性题（含 Stage 3、order_fast、order_cf 胜出题），总分 1,565，与原 V10 留出集逐题分数和 winner 完全一致。
- 固定留出集 100 题的全新检查点重解已完成：100/100 合法、**16,842 步**（与归档留出集总分一致）、最长 314；相对 Stage 3 为 20 改善 / 80 持平 / 0 退化；耗时 192.18 秒（4 进程）。
- **没有**在本次合入中重跑完整 1,000 题。

**影响：** 不能声称"本次合入已独立复现 164,306"。文档统一区分三类口径：

1. 原版研究运行的千题成绩 164,306；
2. 本次合入对交付 CSV 的千题回放验证 164,306；
3. 本次合入的独立重解题数与成绩（10 题 / 1,565；留出集 100 题 / 16,842）。

**建议：** 若需要完整独立复现，在 Linux + GCC 14.2.0 上使用 `--jobs 4`、新检查点运行约 5 CPU 小时；不要复用研究包里的 SQLite 作为求解输入。

## 2. 本机工具链与冻结研究不同

**原任务：** 不修改 V10 核心搜索算法、参数、调度策略、候选路线和搜索预算；检查是否存在工程整合导致的行为差异。

**实际：** 研究成绩由 Linux/GCC 14.2.0 产生；本机只有 Apple Clang 21.0.0 + `compat/bits/stdc++.h`，没有 GCC 或容器。V10 构造器大量使用 `unordered_map`/`unordered_set`，迭代顺序依赖标准库实现，因此不能假设跨工具链逐字节一致。

**验证：** 本机 100 题留出集重解总分 16,842，与归档完全一致；96/100 逐题分数、99/100 winner、92/100 程序与归档 Linux CSV 相同。4 道分数差异题（`scored_0169` 118→117、`scored_0498` 185→184、`scored_0565` 251→248、`scored_0865` 264→269）净和为 0；这 4 题在本机用冻结研究代码重跑均与本移植版逐程序一致，因此差异归因于工具链/`unordered_map` 迭代顺序，不是移植逻辑差异。

**影响：** 不声称跨平台逐字节复现；正式发布仍以交付 CSV 与研究报告为准。

**建议：** 若做发布级逐题回归，在 GCC/libstdc++ 参考环境重跑并用 `src/verify.py` 验证。

## 3. 检查点布局升级，旧 V9 检查点不能直接 resume

**原任务：** 保留 V1–V9 历史复现能力，不破坏现有版本。

**实际：** V10 增加五个内核和生产参数，检查点从 schema 3 / `v9-functional` 升为 schema 4 / `v10-functional`。新代码会明确拒绝旧 V9 检查点并提示回到产生它的提交；`--version v9` 仍可在一个全新检查点上完整复现 V9。V1–V8 仍通过固定 Git 提交的 worktree 复现。

**影响：** 旧 V9 SQLite 不能在新代码上续算；这是指纹校验的预期行为，不是数据损坏。历史 V9 CSV、报告和逐题证据均保留。

**建议：** 需要续算旧 V9 运行时，使用 V9 合入提交的 worktree；不要放宽 schema 4 的指纹校验。

## 4. 模拟器的"默认 V10 Full"与真实求解的边界

**原任务：** 模拟器默认展示 V10 Full，支持 V9/V10 比较、真实结果回放、逐步指令与寄存器、目标标记、实际程序长度、164,306 总分、离线可用。

**实际：**

- 回放槽位扩展为 V1–V10，页面默认选中 `V10 Full`，并显示"V10 Full · 1,000 题 · 164,306 步"。
- 导入 `submissions/elf-calculator-independent-v10-score-164306.csv` 与官方题目 CSV 后，可逐题比较 V9/V10、查看逐步寄存器、目标命中、程序长度和该 CSV 的总步数。
- 浏览器端**没有**嵌入 C++/Python V10 求解器；自定义题仍由页面内置 JavaScript 教学求解器处理，页面明确标注它与 Python/C++ V10 不是同一实现。
- 没有把 2.5 MB 的 V10 CSV 或预计算结果硬编码进 HTML；真实回放需要用户导入 CSV，避免把回放包装成"浏览器独立求解"。

**影响：** "默认展示 V10 Full"体现为默认版本选择、算法说明和成绩展示；未导入 CSV 时不会凭空显示 V10 程序。

**建议：** 若需要完全零导入的演示，可在离线页面内嵌一份小样本回放数据，但必须明确标注"预计算回放"，并避免与真实求解混淆。

## 6. `v10.json` 的 `solver_commit` 字段为 null

**原因：** 报告要随整合提交一起入库，而提交自身的 SHA 在写入文件时不可知；若写入再 amend 会造成自引用不一致。

**实际：** 报告使用 `solver_commit: null` + `solver_commit_note`，完整提交链以 Git 历史为准；这不影响 `build_report.py` 的正式报告校验。

**建议：** 如需机器可读的精确提交，可在后续独立文档提交中补记该提交 SHA，但不要改写历史报告或 CSV。
