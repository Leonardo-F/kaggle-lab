# Santa 2026 · 公开前沿方案对比与本地搜索实验

本文记录 2026-11-23 针对公开前沿提交（`santa-2026-frontier-programs-128-513` notebook，榜单分数 **128,513**）的调研、差距测量和新算法的实验结果。结论先行：**该 notebook 不含求解算法**，它校验并复制一份公开数据集；我们据此实现的值图改写器把正式集总指令数从 270,450 降到 **269,413**（−0.38%），但离 128,513 仍有约 2.1 倍差距。

## 1. 参考 notebook 的实际内容

逐格阅读 `santa-2026-frontier-programs-128-513.ipynb`（9 个 cell）后可以确认：

1. 它从 Kaggle 数据集 `ishankarnick/santa-2026-frontier-programs` 读取 `submission.csv` 与 `sources.csv`，用与官方一致的规则回放 1,000 道题，再复制成自己的提交。
2. 数据集本身是"公开 notebook/数据集逐题取最短程序"的合并结果，作者自述：每几小时拉取一次公开输出、逐题回放取最短，再用公开的 value-graph 搜索（Wang Jakie 的 notebook，经 royalacecat 整理）打磨，约每题目 20,000 轮；2026-11-21 时有 95 题优于所有公开程序，其余与最佳公开程序持平。
3. notebook 里没有搜索、构造或优化代码，只有校验器与来源统计。

因此 128,513 不是"某个算法跑出来的分数"，而是**社区逐题最优程序的并集**。按本仓库 `AGENTS.md` 的自主求解规则，不能把它当作我们的结果；也不在我们的网络与凭据范围内（需要 Kaggle API）。

## 3. 目标结构测试：是否存在可利用的共享结构

对 1,000 道正式题做的检验：

| 检验 | 结果 | 含义 |
| --- | --- | --- |
| 目标之间是否存在 1 条指令的直接关系 | 练习集各家族 0–0.6%（仅 `tiny` 家族 78.6%） | 目标不是彼此的中间值 |
| 目标差集是否近似小分母有理比 | 前 5 题 0 命中 | 不存在 `V·k` 型共享乘子 |
| 目标两两 gcd 是否 > 2^20 | 前 6 题 0 命中 | 不存在共享大因子 |
| 目标是否共享 > 1000 的素因子 | 抽样 200 题中 3–4% | 乘法共享很少 |
| 相邻目标间距 ≤ 2^12 的比例 | 抽样 80 题中 5% | 近邻簇只占少量目标 |
| 所有差值的 gcd | 前 40 题均 < 2^8 | 无隐藏模数结构 |

即：正式题的目标基本是"随机大整数"，需要逐目标构造。公开前沿的 1.8 倍优势**不是**靠发现某种解析式，而是靠更强的联合搜索（在目标之间共享中间值、并反复局部改写）。

## 4. 我们尝试的新算法与实测结果

新增 `graph_solver.py`（值图改写器）。做法：把一份合法程序的**所有产出值**都当作可用操作数（旧求解器只能用当前 48 个活跃寄存器），再逐目标寻找更短的重新推导，循环到不动点，最后重新分配寄存器；每一步都用 `solve.replay` 校验，只保留更短的程序。

包含四个改写族：

1. 单指令重推：`t = a ± b`、`a*b`、`a/b`，`a,b` 取任意已产出值；
2. 双指令重推：`t = (a op b) op c`（中间值落图后可被其它目标复用）；
3. 锚点重推：`t = u + (t-u)`，`u` 为图上邻近值，偏移量递归构造；
4. 隐藏锚点发现：对 `u = a op b` 统计有多少目标满足 `t-u` 已在图上，命中 ≥2 就建 `u` 并让这些目标各用 1 条指令。

实测（正式集 1,000 题，逐版本迭代打磨）：

| 数据 | 改写前 | 改写后 | 变化 |
| --- | ---: | ---: | ---: |
| 练习集 200 题（早期单步版本） | 55,614 | 55,544 | −0.13% |
| 正式集 1,000 题（严格单步版本，不动点） | 270,450 | 270,450 | 0 |
| 正式集 1,000 题（修正锚点接受条件 + 双指令改写，迭代三轮） | 270,450 | 269,706 | −0.28% |
| 正式集 1,000 题（多轮打磨 + 逐题取最短合并） | 270,450 | 269,611 | −0.31% |
| 正式集 1,000 题（锚点变体搜索 + 两轮合并） | 270,450 | 269,474 | −0.36% |
| 正式集 1,000 题（追加变体 6/7、倍增变体 5，再合并） | 270,450 | **269,413** | **−0.38%** |

最终版本：276 题变短、724 题持平、0 题变长；最长程序 525 步（限制 4,096）；`solve.py --check` 独立回放 1,000 题全部通过。改进集中在有链式/近邻结构的题目。严格单步版本之所以是 0，是因为它只接受"立即变短"的改写；放宽为"先接受锚点改写、再按整题长度择优"后，可以跨过局部平台（这正是公开方案里"每题目上万轮打磨"的作用）。

归档：[elf-calculator-score-269413.csv](../submissions/elf-calculator-score-269413.csv)。

另外验证过两条纯求解路线，均未超过现有提交：

* 自顶向下的成本传播规划器（按 `(位宽, 值)` 排序做一次代价传播，再按最小边际成本物化目标）：在练习集抽样上多数题目给不出不劣于参考的程序（预算内不可达或更长），未用于提交。
* 现有 `solve.py` 的全策略组合与多轮 `--refine`：在 100 题抽样上再跑一轮均为 **0** 改进，说明该管线已收敛。
* 跨策略值图合并（把全部策略程序的产出值取并集后重推）：0 改进。
* 目标排序变体（按值、按位宽、正反序 × 多个进制）：0 改进。

### 为什么停在 0.38%

按可达值增长模型：从 4 个 10 位起始值出发，5 条指令可达约 2×10⁹ 个不同值，而随机 47 位目标空间是 1.4×10¹⁴——**随机 47 位目标的下限约 7–8 条指令**（我们 14.5）。要逼近这个下限，必须在上亿级表达式空间里做联合搜索（公开方案自述"每题目两万轮"），而局部改写只能调整已有分解，无法生成全新的分解结构。

## 5. 结论与建议

1. 现有程序在"严格单点改写"下已局部饱和（0 收益），放宽为允许跨平台、多轮变体搜索后再逐题取最短仍有 0.38% 收益；但公开前沿的差距需要**联合搜索**（同时决定建哪些共享中间值、以及所有目标的分解），而不是继续加改写规则。
2. notebook 自述的做法（逐题回放取最短 + 每题目约 20,000 轮 value-graph 打磨）与我们测到的差距量级一致：那是大量算力换来的逐题最优并集，单靠一次性构造难以匹配。
3. 若要继续冲榜，建议按以下顺序投入：先实现"全局共享中间值搜索"（集合覆盖式贪心 + 模拟退火，目标函数为整题指令数），再对每题做多轮局部打磨；预计需要 2–3 天开发与大量 CPU 时间，且收益不确定。
