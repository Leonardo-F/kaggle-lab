01 赛题与手算

每题给定初始正整数列表 starting_values、目标列表 targets、数值上限 value_limit、寄存器数量 registers（正式题为 48）。程序每步读取两个已初始化寄存器，做加、减、乘或整除，将结果写到指定寄存器，允许覆盖操作数。结果必须为正整数且不超过上限；除法要求整除。目标只要曾经出现过即可，包括初值中的目标。单题最多 4,096 条指令，program 单元格最多 128 KiB。正式 1,000 题的指令数相加，越低越好。Kaggle 题面 · 独立验证器

指令 JSON 形式为 [op, i, j, d]，索引从 0 开始。先读 i、j 的旧值，后写 d。

2.1 真实目标：有限寄存器上的最短程序

记输入为 I=(s,T,L,R)\mathcal I=(\mathbf s,T,L,R)，初值集合为 SS，目标集合为 TT。第 kk 条指令为 pk=(o,i,j,d)p_k=(o,i,j,d)。寄存器状态与已命中集合满足

KR⋆(I)=minπ∈F(I)|π|,Q=∑i=11000|πi|.K_R^\star(\mathcal I)=\min_{\pi\in\mathcal F(\mathcal I)}|\pi|,\qquad Q=\sum_{i=1}^{1000}|\pi_i|.

2.2 值依赖图：把程序压缩成共享结构

给每个非初值 vv 选择构造式 v=o(a,b)v=o(a,b)，得到有向无环图（DAG）。令依赖闭包 DG(v)D_G(v) 包含生成 vv 所必需的非初值节点及其自身：

∑t∈T|DG(t)|−C(G)=∑v:m(v)>0(m(v)−1).\sum_{t\in T}|D_G(t)|-C(G)=\sum_{v:m(v)>0}(m(v)-1).

2.3 图更小，程序一定更短吗？

无限寄存器时，一个合法 DAG 可以按拓扑顺序每个有效节点计算一次。反过来，取任一合法程序中每个值首次出现时的构造式，即得到无环依赖图；去掉无用节点，其节点数不大于程序长度。故

minG 合法值图C(G)≤KR⋆(I).\min_{G\text{ 合法值图}} C(G)\le K_R^\star(\mathcal I).

有限寄存器中，同一图可能因活值过多而需要重算，甚至无法被当前编译器成功编译。因此 C(G)C(G) 是搜索代理，不是正式分数，必须完整回放后比较 |π||\pi|。

思考题：目标 100 完成后是否可以立刻释放其寄存器？

从赛题规则看可以覆盖；但从后续依赖看，103 和 107 还要用到 100，提前释放可能迫使重算。必须区分“目标已达成”和“值已无未来用途”。

4.3 多图完整路径联合选择（V6–V7）

对每个目标 tt，从各候选图提取完整见证路径 pt∈Ptp_t\in\mathcal P_t，联合代理目标为

minpt∈Pt|⋃t∈TDt,pt|.\min_{p_t\in\mathcal P_t}\left|\bigcup_{t\in T}D_{t,p_t}\right|.

实现用 Python 整数 bitset 表示依赖集合，并集用按位或，成本用 bit_count()。先初始化及坐标搜索，再模拟退火选择路径。V6 默认路径选择 300 轮；V7 的多图路径选择 400 轮，扰动 1–8 个目标路径，温度由 3 降至 0.15，按 Metropolis 准则接受部分劣解。V7 还对最多两条最短候选执行额外动态融合（每次 120 轮）。最终编译、回放，按真实指令数保留最好合法程序。

练习：为什么每个目标分别选最短路径不一定最优？

设 A、B 的各自最短闭包大小均为 3，且彼此不交；另有各大小为 4 的路线，二者共享三个中间值。分别最短的并集成本为 6，第二组并集成本为 5，因此联合选择可能更优。这个例子只说明集合代理成本，不代表有限寄存器程序一定节省一步。

7.2 动态可达值字典与逆向残差搜索（constructor_wide）

内核从本题初值出发构建一个有限的多表达式字典，它不是完整可达值空间：每个值最多 3 条表达式，已知值与"可一步物化"的值分开记录。种子步骤（按代码顺序，值已存在则跳过）物化稠密的小整数，让后续残差搜索有便宜的起点：

  1. 1 = s0 / s0（若 1 不在初值中）；
  2. 2..16 逐个物化：优先用字典中的一步表达式，否则 v = (v-1) + 1；
  3. 2 的幂：从 32 开始倍增，mode>=3 到 256，否则到 65536。

之后每加入一个新节点，就把它与所有活跃值做加、减、乘、整除（含两种减/除方向）扩充字典。

一步反查。 对目标 v 先扫"一步可达"关系，复用 3.2 节的六种反推：v-a、a-v、v+a（用减法）、v/a（乘法）、v*a（除法）、a/v（除法），并检查每个操作数是否已在已知集合或字典中。若候选依赖不超过 2 个就提前接受。

逆向残差分裂。 一步不成时，把目标拆成"已知乘数 a × 商 q + 残差 r"：

t=aq+r,q=⌊t/a⌋,r=tmoda,t=a q+r,\qquad q=\left\lfloor t/a\right\rfloor,\quad r=t\bmod a,

同时尝试非标准残差（商向上取整）：

t=a(q+1)−(a−r),0<r<a.t=a(q+1)-(a-r),\qquad 0<r<a.

乘数 a 来自 probes/bases：当前已知值，加上按位宽分桶的字典采样（每桶最多 18 个均匀采样；mode 非零时每桶再随机抽 10 个）。分裂代价是启发式估计，越小越先递归：

其中 KK 是已知值集合，bits(q)=64−clz(q)\operatorname{bits}(q)=64-\operatorname{clz}(q)。按 cost 排序后最多展开 width 个互不相同的分裂；先递归构造 q（深度减 1），再依次补 a、乘积 aqaq（若字典已有则直接取）与最终一步。递归带 memo；没有候选时退化为固定基数 fallback（v<256v<256 用 16，否则用 256；若 a≥va\ge v 则改用 2，再递归拆商与余数）。深度 5 与 width 6 都是冻结上限；depth=5 时还会把所有字典键加入分裂基底扫描，扩大候选范围。

小例子： 初值 {3, 7}、上限 120、目标 103。种子先物化 1=3/3 与 2..16（10 可由 3+7 进入字典并物化）。取乘数 a=10：q=10、r=3，10 已物化、3 是初值，只新增 100=10×10 与 103=100+3 两个节点。这里的关键不是"乘积形式"本身，而是 a 与 r 的选择在构造期就按代价排序，不需要先有 V8 那样的完整候选图。

7.3 MITM 商邻域（constructor_mitm）

constructor_mitm 与 wide 的差异只在候选分裂的搜索范围：在递归 depth≥4 的阶段增加全字典商邻域匹配。对每个基底 a 与商 q=⌊v/a⌋q=\lfloor v/a\rfloor，在已排序的全值表 V（已知值 + 字典值）中用二分定位 q，取 q 附近窗口（源码为位置 pos-5 .. pos+5，最多 11 个候选 b）。对每个 b 计算乘积与残差：

p=ab,r=|p−v|,t={p−r,p>v,p+r,p≤v.p=a b,\qquad r=|p-v|,\qquad t= \begin{cases} p-r, & p>v,\\ p+r, & p\le v. \end{cases}

合法条件是 1≤p≤L1\le p\le L、p≠vp\ne v、r≠vr\ne v（避免自依赖）。通过检查时把 (a,b,r,±)(a,b,r,\pm) 作为一个分裂候选，交给与 wide 相同的代价排序与递归构造。

这不是穷举四元组： 这里的 "MITM" 指用乘积/商邻域把目标拆成"已知值 × 商附近的字典值 ± 残差"，而不是枚举所有 (a,b,c,d)(a,b,c,d) 组合。它只扫描有界的 bases 集合，并对每个 q 看至多 11 个邻域值；用二分定位后复杂度约为 O(|bases|·log|V|·11)O(|\text{bases}|\cdot\log|V|\cdot 11)，远小于四元组穷举。它也不保证覆盖所有可行分解。

例子： v=1003、a=64、q=15；q 的邻域含 16，于是 p=64×16=1024、r=21，得到 1003 = 1024 − 21。若 1024 与 21 都便宜（字典命中或由已有值一步得到），这条路线可能比 64×15+43 更省；也可能更差，最终由代价排序和回放决定。

7.4 两轮图压缩（polish）

构造出的图里可能有"独占依赖子树"：只被当前值 v 使用的祖先集合 R(v)R(v)。polish 尝试用更小的后缀表达式重建 v，从而删掉 R(v)R(v) 中不再需要的节点。对候选新表达式 e（直接一步反推，或经两两运算池引入一个辅助值 b 的两步构造），增益为

gain(v,e)=|R(v)|−|D(e)⧵F|,\operatorname{gain}(v,e)=\left|R(v)\right|-\left|D(e)\setminus F\right|,

其中 FF 是活跃节点中不属于 R(v)R(v) 的固定部分，D(e)D(e) 是新表达式的依赖闭包。只接受 gain>0\operatorname{gain}>0 的补丁并原地改图。每轮按独占依赖子树大小降序只评估前 20 个活跃值，共 2 轮；两轮后重新编译，只有严格更短才替换该路线的 Stage 1 程序。polish 是受限局部改写：候选来自"已有值一步反推 + 两值池一步中转"，不改变闭包外的结构，不保证最优。

7.5 Stage 1 编译：8 个确定性顺序

compile_graph 对给定值 DAG 尝试 8 个确定性拓扑/DFS 顺序（seed 919），每次都真正生成指令并回放验证。顺序差异来自：

  • 目标根顺序：turn % 4 为 0 用原序、1 用逆序、2 按闭包大小排序（turn % 8 == 6 时降序）、3 用 Random(919) 打乱；
  • 操作数次序：每个节点的两个操作数按闭包大小交换，交换方向随 turn % 2 变化；
  • 寄存器分配：优先最小空闲寄存器；无空闲时在当前指令的受保护集合之外淘汰"下一次使用最远"的值，rank 为 (下一次使用距离)/(turn % 2 ? 1+闭包大小 : 1)，再按距离、负闭包大小、值打破平局；
  • 回放：失败即丢弃该顺序；某个顺序的指令数达到 DAG 节点数下界时提前停止。

返回值是 (最短合法程序, 最后一次执行的 order 长度)。第二个返回值保留了冻结研究的指标语义：它是最后一次尝试的 order 长度，不总是返回程序本身的长度；四路线明细里的 nodes 沿用了这一语义，不能把它当作精确节点数。顶层指标 nodes 不是这个值，而是 Stage 2 首现 DAG 的节点数（固定 DAG 下界，见 7.6）。

pressure(π)=(overflow,peak,area),overflow=∑kmax(0,|Lk|−R),peak=maxk|Lk|,area=∑k|Lk|,\operatorname{pressure}(\pi)=(\operatorname{overflow},\operatorname{peak},\operatorname{area}), \quad \operatorname{overflow}=\sum_k\max(0,|L_k|-R), \quad \operatorname{peak}=\max_k|L_k|, \quad \operatorname{area}=\sum_k|L_k|,

8.2 算术构造与计算图的数学原理

所有构造器输出的都是一张值依赖图 G=(V,E)G=(V,E)：节点是正整数，边表示"由两个已有值经一次运算得到"。初值集合 SS 是免费节点，目标集合 TT 必须被覆盖。一条指令对应一个节点的一次求值：

v=a∘b,∘∈{+,−,×,/},1≤v≤L,v=a\circ b,\qquad \circ\in\{+,-,\times,/\},\qquad 1\le v\le L,

其中除法要求整除。V10 的构造器不直接生成寄存器程序，而是选择表达式图；compile_graph 和 schedule 再把图编译成有限寄存器上的指令序列。

动态字典。 内核只保留一个有界字典 DD：每个值最多 3 条表达式，已物化值集合 KK 与"可一步物化"的字典值分开。加入节点 vv 后，把它与所有活跃值 aa 做

a+b,a−b,b−a,ab,a/b (b∣a),b/a (a∣b),a+b,\quad a-b,\quad b-a,\quad ab,\quad a/b\ (b\mid a),\quad b/a\ (a\mid b),

并把新值放进字典。因此构造是"从初值出发的有限闭包"，不是完整可达值枚举。

逆向残差。 对目标 tt 和基底 aa，V10 使用两类分裂：

t=aq+r,q=⌊t/a⌋, r=tmoda,t=aq+r,\qquad q=\left\lfloor t/a\right\rfloor,\ r=t\bmod a,
t=a(q+1)−(a−r),0<r<a.t=a(q+1)-(a-r),\qquad 0<r<a.

递归构造 qq（深度减 1），再补 aa、乘积 aqaq 与最后一步。深度上限 5、每层最多 width=6 个分裂，因此这是有界搜索；memo 只缓存当前目标构造过程中的子结果。

压力感知构造（constructor_pressure）。 它把"这个值离上次使用多久"和"它的依赖链多深"折算成一个非负价格。设全局时钟 tick 在每次 add 时递增，used_at[v] 是 vv 最近一次作为操作数或结果的时间，depth[v] 是依赖深度：

p(v)=0.12·min(2,tick−used_at(v)64)·min(4,depth(v)),v∉S.p(v)=0.12\cdot\min\left(2,\frac{\mathrm{tick}-\mathrm{used\_at}(v)}{64}\right)\cdot\min(4,\mathrm{depth}(v)), \qquad v\notin S.

初值与未物化值不参与这个价格（初值价格为 0，字典虚拟值按 1 或位宽估计）。一个候选计划 PP 的代价是

plan_cost(P)=|P|+∑x∈Ext(P)p(x),\operatorname{plan\_cost}(P)=|P|+\sum_{x\in \operatorname{Ext}(P)} p(x),

其中 Ext(P)\operatorname{Ext}(P) 是计划中引用、但当前尚未物化的外部值。leaf 在字典的至多 3 条表达式中选"两个操作数压力之和"最小者；update 也只按 plan_cost 严格更小替换候选。这样构造阶段就会偏向"便宜、近、浅"的操作数，而不是只看节点数。

联合构造（constructor_joint / constructor_cf）。 对两个未覆盖目标 t,ut,u，尝试一个共享枢轴 hh：

t=ah+r,u=bh+s,t=ah+r,\qquad u=bh+s,

其中 a,ba,b 是候选比例，r,sr,s 是可正可负的小残差。给定 (a,b)(a,b) 后，候选枢轴取

h∈{⌊ta⌋,⌊ta⌋+1,⌊ub⌋,⌊ub⌋+1,⌊t+ua+b⌋,⌊t+ua+b⌋+1},h\in\left\{\left\lfloor\frac{t}{a}\right\rfloor, \left\lfloor\frac{t}{a}\right\rfloor+1, \left\lfloor\frac{u}{b}\right\rfloor, \left\lfloor\frac{u}{b}\right\rfloor+1, \left\lfloor\frac{t+u}{a+b}\right\rfloor, \left\lfloor\frac{t+u}{a+b}\right\rfloor+1\right\},

并要求 2≤h<min(t,u)2\le h<\min(t,u)、ah≤Lah\le L、bh≤Lbh\le L、|r|<t|r|<t、|s|<u|s|<u。联合代价为

c(h,a,b)=p(h)+p(a)+p(b)+p(|r|)+p(|s|)+2+1r≠0+1s≠0.c(h,a,b)=p(h)+p(a)+p(b)+p(|r|)+p(|s|)+2+\mathbf 1_{r\ne0}+\mathbf 1_{s\ne0}.

计划按"先构造 hh，再补 a,ba,b，再发 ahah 与 bhbh，最后加/减残差"生成；生成后必须通过依赖完整性检查（每个操作数要么已知、要么在本计划中更早出现），并确认 t,ut,u 都被覆盖。只有当联合计划相对"分别单独构造 tt 与 uu"的 plan_cost 至少省 2 时才会被接受。

constructor_joint 用 bases 集合和 b≈ua/tb\approx ua/t 的整数近似生成 (a,b)(a,b)；constructor_cf 改用 u/tu/t 的连分数。设 u/t=[k0;k1,…]u/t=[k_0;k_1,\ldots]，其收敛项 pi/qip_i/q_i 满足 pi/qi→u/tp_i/q_i\to u/t；源码枚举有界半收敛项

ba=p0+jp1q0+jq1,j∈{1,⌊cap2⌋,cap−1,cap},\frac{b}{a}=\frac{p_0+jp_1}{q_0+jq_1}, \qquad j\in\left\{1,\left\lfloor\frac{\text{cap}}{2}\right\rfloor,\text{cap}-1,\text{cap}\right\},

其中 cap 同时受下一项商 kk 和 2202^{20} 的数值上限约束。这样比 joint 的邻域更系统地找到"小整数比例"，但两者都只保留代价最小的前 4 个提案，且每个目标对只尝试一次。

8.3 寄存器压力与实际指令数的关系

图节点数只是下界：一个图有 NN 个非初值节点，至少需要 NN 条指令，但有限寄存器会迫使调度器重算某些值，实际指令数可能大于 NN。V10 继续使用 V9 的压力三元组作为候选顺序的排序代理：

overflow=∑kmax(0,|Lk|−R),peak=maxk|Lk|,area=∑k|Lk|,\operatorname{overflow}=\sum_k\max(0,|L_k|-R),\qquad \operatorname{peak}=\max_k|L_k|,\qquad \operatorname{area}=\sum_k|L_k|,

其中 LkL_k 是第 kk 步的活值集合，RR 是寄存器数。压力三元组只用于排序，不用于最终接受；每个候选都必须实际 emit 并 replay。V10 的改进不是在调度器里加新公式，而是：

  • 让更多图进入调度器。 V10.1 对四个 Stage 1 路线产生的每个不同 DAG 都重新调度，而不是只调度最短编译程序的那一个；候选按 (编译节点数, 程序长度) 排序，节点数已经不小于当前最优时直接跳过（对固定候选成立的下界）。
  • 构造期就考虑压力。 constructor_pressure 的 plan_cost、constructor_joint 的 price 与 order_* 的 readiness 都把压力价格放进候选估价，使"图更小"与"调度后更短"更一致。
  • 修复重复计算。 反馈修复显式统计每个值在程序中出现的次数，优先替换被重复计算且闭包大的值。

因此 V10 的 nodes 指标仍然只是固定候选 DAG 的下界，不是全局下界；它的收益来自候选图更多、更便宜，而不是证明了某个图的最优调度。

8.4 目标顺序：Order Fast 与 Order CF

V9 的目标顺序基本由输入顺序/简单排序决定。V10 的 constructor_order_fast 在每轮从未覆盖目标中选一个，先估它的"就绪代价"：

ready(t)={0,t∈K,1,t∈D⧵K,min{max(2,0.23(bits(t)−7)),\ mina∈A,2≤a<t[1+c(q)+1r≠0(1+c(r))]},否则,\operatorname{ready}(t)= \begin{cases} 0,&t\in K,\\ 1,&t\in D\setminus K,\\ \min\left\{\max(2,0.23(\operatorname{bits}(t)-7)),\ \min_{a\in A,\,2\le a<t}\left[1+c(q)+\mathbf 1_{r\ne0}\left(1+c(r)\right)\right]\right\},&\text{否则}, \end{cases}

其中 q=⌊t/a⌋q=\lfloor t/a\rfloor、r=tmodar=t\bmod a，AA 是活跃值集合，

c(x)={0,x∈K,1,x∈D⧵K,max(2,0.23(bits(x)−7)),否则.c(x)= \begin{cases} 0,&x\in K,\\ 1,&x\in D\setminus K,\\ \max(2,0.23(\operatorname{bits}(x)-7)),&\text{否则}. \end{cases}

再估计该目标对其他未覆盖目标的共享收益：

benefit(t)=∑u≠t(1u≡0(modt) ∧ u/t∈K+1|u−t|∈K),\operatorname{benefit}(t)=\sum_{u\ne t}\left(\mathbf 1_{u\equiv0\pmod t\ \land\ u/t\in K} +\mathbf 1_{|u-t|\in K}\right),

选择

t\*=\argmint(ready(t)−0.35min(4,benefit(t))).t^\*=\arg\min_{t}\left(\operatorname{ready}(t)-0.35\min(4,\operatorname{benefit}(t))\right).

直观上，先做"便宜且能解锁其他目标"的值。constructor_order_cf 使用同一目标选择，但对被选中的目标额外调用 constructor_cf 的枢轴联合提案，因此它同时改变"先做哪个"和"这个目标与哪个目标共享枢轴"。

两条 order 路线都只改变构造顺序/候选，不改变 Stage 1 编译器和 Stage 2 调度器；它们的输出仍是值 DAG，之后走同一套 compile_graph + schedule。

8.5 多路线搜索与合法候选择优

V10 Full 的候选来源与顺序是冻结的：

  1. Stage 1 四路线：wide 6:3、wide 6:4、mitm 6:3、mitm 6:4；每条 raw + polish，各用 8 序编译。
  2. 联合调度（V10.1）：取编译最短路线作为基线，先做 Stage 2 调度；再把其他路线的 raw/polish 程序按 (nodes, length) 排序，逐个提取首现 DAG、去重、重新调度。只有严格更短才替换。
  3. pressure 6:3 / 6:4：每个 mode 的 raw 与 polish 都编译、调度、回放，严格更短才替换。
  4. 精确反馈修复（V10.2）：两轮；每轮最多选 16 个"重复计算 × 闭包"高的值，枚举反推表达式补丁，按代理 nodes+0.08·excess+0.004·area 排序，最多 8 次编译/调度尝试，每个被替换节点最多 2 次；只有实际 replay 更短才接受。
  5. joint / cf：两条原生联合构造路线，各走 8 序编译 + 调度；Stage 3 取三者最短。
  6. order_fast / order_cf：两条目标顺序路线，各走同一编译/调度；Full 在 Stage 3、order_fast、order_cf 三者中取严格最短。

所有候选都从当前题目行重新构造，回放合法性由内部 replay 检查，最终导出再由 verify.py 全量独立验证。没有候选时不会用历史答案补齐。

平局规则。 路线/候选比较一律"严格更短才替换"，等长保留先到者；Stage 1 四路线顺序固定；Stage 2 的候选顺序、随机种子（202609）和 6 种淘汰策略固定；V10 没有引入新的随机种子。等长程序在不同标准库下可能因 unordered_map 迭代顺序不同而选择不同寄存器，因此不声称跨工具链逐字节一致。

9.2 值依赖图与原生构造

一道题的解是一个值依赖图 G=(V,E)G=(V,E)。每个非初值节点 vv 有一条入边 (v,o,a,b)(v,o,a,b)，表示

v=a∘b,∘∈{+,−,×,÷},v = a \circ b,\qquad \circ\in\{+,-,\times,\div\},

其中 a,ba,b 是初值或已经出现的值，除法要求整除，所有值满足 1≤v≤L1\le v\le L。目标的闭包必须全部被覆盖，寄存器数量只影响执行顺序，不影响图本身是否合法。

V11 的四个 r8 内核都从目标出发做残差分解：把目标写成 v=a·q+rv=a\cdot q+r，递归构造 qq，再把 aa、qq、vv 用乘法/加法/减法拼回去；差别在于候选 (a,q,r)(a,q,r) 如何枚举和排序：

内核 候选生成的核心思想 研究轮次
order 按"就绪代价 + 共享收益"排序目标与基底；逆向残差分裂 早期 R1–R4 基线
factor 因子残差：优先尝试整除分解，再补小残差 R1–R3
bilayer 两层虚拟字典：常用中间值可被多个目标复用 R7–R8
congruence 同余匹配 r≡±t(moda)r\equiv \pm t\pmod a，允许非规范残差 R5

四者使用相同的宽度 6、深度 3 和超时预算，因此它们的差异是候选空间的差异，不是预算差异。原生源码保持冻结研究的字节一致（8 个 .cpp 逐字节相同），见 原生构建 与 V11 研究记录。

9.3 超图联合：从候选边中选一张共享图

四个内核各自会产出一些值图。同一个值 vv 可能有多种表达式，例如

100=10×10=110−10=97+3=⋯100=10\times10=110-10=97+3=\cdots

V11 把所有候选表达式收集成超图：值 vv 的候选边集合 EvE_v，每条边 (v,o,a,b)(v,o,a,b) 连接两个操作数。然后选一组边，使每个目标都有定义、每个被选中的操作数也有定义，并尽量少选边。设 ye∈{0,1}y_e\in\{0,1\} 表示选边，xv∈{0,1}x_v\in\{0,1\} 表示值 vv 被保留，一个可读的整数规划是

min∑v∉Sxvs.t.xv=1(v∈S∪T),∑e∈Evye=xv(v∉S),xae≥ye,xbe≥ye(e∈Ev),ye=0(若边会造成环).\begin{aligned} \min\quad &\sum_{v\notin S}x_v\\ \text{s.t.}\quad &x_v=1 &&(v\in S\cup T),\\ &\sum_{e\in E_v}y_e=x_v &&(v\notin S),\\ &x_{a_e}\ge y_e,\quad x_{b_e}\ge y_e &&(e\in E_v),\\ &y_e=0 &&(\text{若边会造成环}). \end{aligned}

实际实现（optimize.py）用更紧凑的等价形式：先以种子图做一次 DFS 得到拓扑 rank，只保留操作数 rank 更小的边，从构造上排除环；再对每个值加"被选边数等于是否保留"，对每个操作数加"使用该值的边数不超过该值被保留数"，最后用“选中边数不超过种子图节点数”限制总边数。目标函数是选边数（图节点数的代理），不是最终寄存器指令数；因此 MILP 只负责产生更好的图候选，真实长度仍由调度与回放决定。

科学计算上这是 SciPy 的 HiGHS 整数规划，带 0.7 秒墙钟上限；超时返回当前 incumbent 或种子图。它不是全局最优求解器，也不保证跨机器逐题复现——这一点和 V9/V10 的限时子搜索相同。

9.4 二步、三步与四步合成

MILP 之后，V11 还会尝试把昂贵子图替换成更短的局部表达式。给定当前图，取其中一个要被替换的值 vv，枚举

v=a∘b,v=(a∘b)∘c,v=((a∘b)∘c)∘d,v = a\circ b,\qquad v=(a\circ b)\circ c,\qquad v=((a\circ b)\circ c)\circ d,

其中 a,b,c,da,b,c,d 取自当前图或便宜的可达值。synth 的 mode 2/3 对应二步/三步合成；自由基底组额外使用 synth_extended 的 mode 4 做四步合成。合成只接受实际回放更短的结果，并受固定的枚举预算限制。

这里的思想与 V6/V7 的"子图重写"相同，但 V11 不运行 V8 的两轮 polish 链：它在新构造的值图上做有限合成，再交给调度器，而不是对历史程序做通用改写。

9.5 寄存器压力调度与局部搜索

图只给出"要算哪些值"，真正提交的是寄存器指令序列。V11 沿用 V9 引入的两阶段思路，但参数与实现按当前候选重新组织：

  1. 编译（graph.py）：把图变成拓扑序，尝试 4 个确定性顺序（tries=4），用贪心寄存器分配产生初始程序；寄存器不足时按"下次使用距离 / 闭包大小"驱逐并重算。
  2. 压力调度（schedule.py）：在首现 DAG 上枚举目标顺序与求值顺序，用压力三元组（定义见下）排序候选；取前 12 个顺序 × 6 种驱逐策略实际 emit 并 replay，只有严格更短才替换。随机种子固定为 202609。
  3. 调度局部搜索（schedule_local.py）：对目标根顺序做 180 步模拟退火，种子 8821，温度 2(1−(kmod45)/45)+0.052(1-(k\bmod45)/45)+0.05，目标仍是压力三元组；任何 emit 结果都必须通过 replay。

压力三元组定义为

(excess, peak, area)=(∑kmax(0,|Lk|−R), maxk|Lk|, ∑k|Lk|),(\text{excess},\ \text{peak},\ \text{area}) =\Big(\sum_k\max(0,|L_k|-R),\ \max_k|L_k|,\ \sum_k|L_k|\Big),

其中 LkL_k 是第 kk 步的活值集合，RR 是寄存器数。它只是排序代理。一个图有 NN 个非初值节点时，程序至少有 NN 条指令；有限寄存器会迫使重算，实际长度可能更大。V11 的所有接受决策都用真实指令数，不用代理值冒充分数。

13.1 候选池中的精确图选择模型

给定有限候选值集合 VV，每个非初值 v 对应合法表达式集合 EvE_v；xvx_v 表示保留值，yey_e 表示选择表达式，hv∈{0,…,|V|−1}h_v\in\{0,\ldots,|V|-1\} 表示拓扑层次。M=|V|M=|V|。可建模为

min∑v∈V⧵Sxvs.t.xv=1(v∈S∪T),∑e∈Evye=xv(v∈V⧵S),xae≥ye,xbe≥ye(e∈Ev),hv≥hae+1−M(1−ye)(e∈Ev),hv≥hbe+1−M(1−ye)(e∈Ev),hs=0(s∈S).\begin{aligned} \min\quad &\sum_{v\in V\setminus S}x_v\\ \text{s.t.}\quad &x_v=1 &&(v\in S\cup T),\\ &\sum_{e\in E_v}y_e=x_v &&(v\in V\setminus S),\\ &x_{a_e}\ge y_e,\quad x_{b_e}\ge y_e &&(e\in E_v),\\ &h_v\ge h_{a_e}+1-M(1-y_e) &&(e\in E_v),\\ &h_v\ge h_{b_e}+1-M(1-y_e) &&(e\in E_v),\\ &h_s=0 &&(s\in S). \end{aligned}

选中表达式强制两个操作数同时被选中且拓扑层更早，从而避免环；反之任何候选池内的合法 DAG 均可赋予拓扑层次。该模型优化的是有限候选池、无限寄存器松弛下的图成本，不是完整赛题最优性；也未用于表中任何正式版本成绩（包括 V8、V9、V10 与 V11；V11 只在受限超图 MILP 中使用近似的选边模型做候选生成）。

13.2 V11 之后的开放问题

V11 把独立全量成绩从 164,306 降到 158,955，但没有解决最优性问题。当前明确的边界是：

  • 全局最优未知。 V11 只比较两组候选、固定深度/宽度/预算产生的值图；超图 MILP 只优化选边数，不直接优化寄存器指令数，也没有最优性证书。
  • 代理与真实分数分离。 MILP 的目标是图规模，调度器先用压力三元组排序，最终接受一律看 replay 的真实长度。任何只报告代理指标的"改进"都不能算成绩。
  • 工具链差异。 原生内核遍历 unordered_map，Apple Clang/libc++ 与冻结记录的 Linux GCC/libstdc++ 可能在等长候选上选择不同寄存器；V9 已有 1/1,000 等长差异，V10/V11 不声称跨平台逐字节一致。
  • 墙钟敏感。 超图 MILP 使用 0.7 秒墙钟上限，调度局部搜索固定 180 步；不同机器和负载可能改变候选择优，尤其是 MILP 超时时的 incumbent。
  • 未使用的路线。 V11 没有 LNS、全局锚点、大整数构造或新的全局下界；R16 之后的多基底实验没有进入正式候选，公开前沿分析中调研的共享池/LNS 方向也没有进入当前管线。
  • 口径。 158,955 是本地独立验证的指令总数，不是 Kaggle 榜单成绩；158,585 是 V8–V11 归档择优，不是独立算法版本；174,884 是 V8+V9 后处理归档。三者都不进入独立版本曲线。
  • 练习题独立。 200 题练习集与正式 1,000 题是不同数据集，不能混算或拼成一条曲线。

13.3 相关研究

  • Bos 与 Coster，Addition Chain Heuristics, CRYPTO ’89：加法链和多目标共享。Santa 还允许其他运算、有限数值与有限寄存器。
  • Sethi 与 Ullman，The Generation of Optimal Code for Arithmetic Expressions, JACM 1970：有限寄存器上的表达式求值。Santa 还要选择跨目标共享的表达式图。

学习总结： Santa 的难点不是单独计算一个数，而是同时选择多个目标的构造路径，复用有价值的中间结果，并在有限寄存器内将图编译为最短合法程序。当前 V11 用两组互补候选解决这个问题：多图组合组（order/factor/bilayer/congruence → 超图 MILP → 二步/三步合成）和自由基底组（order + 自由基底 → 三步/四步合成），两组共用 DAG 编译、寄存器压力调度、调度局部搜索和独立回放，逐候选按真实指令数取最短。V11 的本地千题研究成绩是 158,955（1,000/1,000 合法，最长 348），相对 V10 的 164,306 少 5,351 步；r8 单组 161,446、basis 单组 161,711；V8–V11 归档择优为 158,585，只是后处理上界。V1–V10 的本地全量成绩与逐题证据保留在 docs/reports/，旧运行代码保留在 Git 提交中；158,955、164,306 与 175,604 都是本地独立验证的指令总数，不是 Kaggle 榜单成绩，也不是全局最优证明。
