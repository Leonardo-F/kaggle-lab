# 两个赛题的解题思路与阅读指南

整理：2026-11-11（UTC）。依据本仓库 `a0b02f0` 的实际内容、比赛官方说明及下列文档中的一手资料。

这组笔记回答三个问题：**题目究竟优化什么、哪些方法值得尝试、怎样确认改进真实有效。** 它是一份研究路线，不表示其中的优化器已经实现，也不承诺名次或得分。

## 2. 两条路线的区别

| 项目 | 正方形装箱 | Google 量子电路编译 |
| --- | --- | --- |
| 核心工作 | 几何布局、连续优化、结构搜索 | 可逆算法、数值近似、辅助空间管理、资源建模 |
| 提交物 | 1 个 CSV，覆盖 `n=1…1000` | 1 个 ZIP，包含三个子题的电路和化学数值文件 |
| 得分方向 | 总分越低越好 | 三项成本改善倍数的几何平均越高越好 |
| 可以独立改进的单元 | 每个 `n` 的排布 | 每个 benchmark；化学内部的文件必须保持一致 |
| 目前仓库已具备 | 单文件离线 HTML、格点生成、CSV 导入导出、本地几何检查 | 成本公式计算器、测试、背景笔记 |
| 当前最大缺口 | 官方高精度验证流程和强初始排布库 | 官方环境、三项完整可验证 baseline、电路生成器 |
| 推荐第一个小成果 | `n=5` 旋转构造通过官方检查，并替换全量 CSV 中的该实例 | `invsqrt` baseline 完整复现，资源报告与误差报告对应同一个电路文件 |

## 3. 推荐推进方式

**装箱先建立可靠的每题最优候选库，量子编译先跑通三个子题的官方验证。** 两条路线都先留下一份可回退的结果，再一次改变一个主要因素。

装箱的先后顺序：

1. 复现格点分数与完整 CSV，接入官方区间验证。
2. 用 `n=5` 理解旋转，再实现可参数化的排布族。
3. 建立逐题合并、相邻规模迁移与小规模局部优化。
4. 根据单位计算时间的得分收益，决定是否进入接触图精修、断层拼接和 GPU 搜索。

量子编译的先后顺序：

1. 固定官方数据、验证器及依赖版本，三项参考提交均通过完整本地验证。
2. 以 `invsqrt` 学习“近似误差—门成本—工作空间”的闭环。
3. 以 `dqi` 的工作空间和解码器结构为重点，比较完整 `R(ε₊)Q²T`。
4. 先固定化学分解优化 ANGLE/QROM，再研究分解、量化与加载的联合设计。

这是按可理解性和工程依赖给出的顺序。实际完成资源剖析后，如果另一子题出现更明确、可复现的收益，就调整投入，不机械遵循题号。

## 4. 用同一套实验习惯避免误判

每个保留下来的候选都记录以下信息：

| 字段 | 用途 |
| --- | --- |
| 输入数据版本、生成代码 commit、参数和随机种子 | 能重建结果 |
| 生成文件的 SHA-256 | 确认检查、比较、提交的是同一个文件 |
| 起始 baseline、变化内容、运行预算 | 区分算法改进与多花算力 |
| 本地筛查结果、官方完整验证结果、平台回执 | 区分不同强度的证据 |
| 完整目标函数及分项 | 防止只改善一个看起来漂亮的数字 |
| 来源、作者、版本、许可证 | 复用外部方案时可追溯 |

“数值模型通过”“浮点检查通过”“官方本地验证通过”“Kaggle 已评分”应是四种不同状态。文档和界面都不把前三者直接写成最后一种。

轻量起步可采用 Python 命令行、JSON/CSV 实验记录和现有 HTML。无需先搭建庞大的统一平台。浏览器负责观察与比较，长时间优化和正式验证由脚本执行。
